## 6. ملاحظات أمان وخصوصية ذات أولوية

### SEC-APK-001 — السماح بالاتصال غير المشفر
**الأولوية: P0 — مانع للإطلاق حتى التحقق والمعالجة**

AndroidManifest يضم android:usesCleartextTraffic="true".

هذا يسمح للتطبيق بإجراء اتصالات HTTP غير مشفرة، ما لم توجد سياسة شبكة أدق تمنعها. وجود HTTPS في بعض عناوين الخدمات لا يلغي الخطر العام.

**الإجراء المطلوب:**
1. حصر كل الاتصالات الخارجية والداخلية.
2. تحويل كل الخدمات التي يملكها المشروع إلى HTTPS/WSS.
3. مراجعة أي استثناء HTTP لخدمة قديمة.
4. إزالة السماح العام cleartextTraffic أو تقييده عبر Network Security Config باستثناءات محددة ومبررة.
5. اختبار فشل الاتصال غير المشفر بعد الإصلاح.

### SEC-APK-002 — Android Auto Backup مفعّل
**الأولوية: P0 حتى إثبات نطاق النسخ الاحتياطي**

التطبيق يعلن android:allowBackup="true"، ولم يظهر في AndroidManifest المدمج تصريح dataExtractionRules أو fullBackupContent.

قد يؤدي ذلك إلى إدراج بيانات تطبيق محلية ضمن آليات النسخ الاحتياطي للنظام، حسب قواعد Android والملفات ومزود الخدمة. لا يثبت هذا الفحص أن بيانات طبية فعلية تُنسخ، لكنه يتطلب حسم سياسة النسخ.

**الإجراء المطلوب:**
- جرد قواعد البيانات المحلية والتفضيلات والملفات والرموز.
- تحديد البيانات التي يسمح بنسخها وتلك التي يجب استثناؤها.
- إضافة backup/data extraction rules صريحة، أو تعطيل النسخ الاحتياطي إذا كان ذلك الأنسب.
- اختبار النسخ والاستعادة على Android حديث.
- عدم تضمين بيانات حساسة أو جلسات اعتماد ضمن النسخ غير المحمية.

### SEC-APK-003 — أذونات حساسة تحتاج تبريراً
**الأولوية: P1**

يتضمن Manifest أذونات منها:
- SYSTEM_ALERT_WINDOW
- READ_PHONE_STATE
- CALL_PHONE
- WRITE_EXTERNAL_STORAGE
- USE_FULL_SCREEN_INTENT
- SCHEDULE_EXACT_ALARM
- ACCESS_FINE_LOCATION
- ACTIVITY_RECOGNITION
- CAMERA وRECORD_AUDIO

بعضها قد يكون مطلوباً لميزات معلنة مثل المكالمات والموقع والتنبيهات؛ لكن يجب إثبات ضرورة كل إذن، وتوقيت طلبه، ووجود بديل أقل امتيازاً. أذونات النوافذ العائمة وقراءة حالة الهاتف وإجراء المكالمات تستلزم مراجعة خاصة لأنها قد تتجاوز ما يحتاجه مسار VoIP المعتاد.

### SEC-APK-004 — اشتراط وجود كاميرا
**الأولوية: P1**

Manifest يعلن android.hardware.camera مع required=true. هذا قد يمنع تثبيت التطبيق على أجهزة لا تعلن ميزة الكاميرا، رغم إمكانية استخدام بقية خدمات المنصة عليها.

**الإجراء المطلوب:** جعل الكاميرا اختيارية إذا كانت بقية وظائف المنصة يجب أن تعمل دونها، واختبار مكالمة صوتية واستخدام التطبيق على جهاز بلا كاميرا.

### SEC-APK-005 — التخزين الخارجي القديم
**الأولوية: P1**

android:requestLegacyExternalStorage="true" موجود مع targetSdk 36، كما توجد أذونات تخزين قديمة. يجب التأكد من أن إدارة الملفات تستخدم Storage Access Framework أو MediaStore أو APIs الحديثة، وإزالة الأذونات غير اللازمة.

## 8. حدود الفحص

هذا الفحص ساكن ومبني على APK وسجلات GitHub Actions. لم يتم:
- تثبيت التطبيق على جهاز فعلي أو محاكي.
- اختبار تسجيل الدخول أو OTP أو Firestore.
- اختبار قواعد الخادم أو صلاحيات المستخدمين.
- تنفيذ اتصال حي مع Suga أو LiveKit أو Nextcloud.
- اختبار المكالمات والإشعارات والوسائط.
- فحص قواعد النسخ الاحتياطي أثناء الاستعادة.
- إجراء اختبار اختراق أو تحليل ديناميكي.
- مقارنة شهادة التوقيع مع إصدار منشور سابق.

لذلك لا يمكن وصف التطبيق بأنه آمن أو جاهز للإنتاج بناءً على هذا التقرير وحده.

## 10. قرار الفحص

**الحالة: BUILD VERIFIED / RELEASE NOT APPROVED**

- البناء: ناجح وفق سجل CI.
- سلامة أرشيف APK: ناجحة.
- توقيع الإصدار: v1 وv2 موثقان في سجل CI، والشهادة العامة مستخرجة.
- جاهزية الإطلاق النهائي: غير معتمدة.
- المخاطر المانعة: السماح العام بالاتصال غير المشفر، وسياسة النسخ الاحتياطي، وعدم حسم مطابقة versionCode وشهادة التوقيع مع الإصدار السابق.

**الخطوة الهندسية التالية:** إصلاح إعدادات Manifest والسياسات المرتبطة بها على فرع إصدار منفصل، ثم بناء APK جديد وتشغيل اختبارات إعادة التحقق، مع عدم تغيير أسرار التوقيع أو مفاتيحه.
